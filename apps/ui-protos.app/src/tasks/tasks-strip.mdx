# Tasks and outputs

The workspace's bottom strip, opened. A request that does work becomes a **task**: a plan, the
steps it took, the files it made. The assistant panel shows a task where it was asked; this strip
shows **all** of them, from every chat, so the user can see what is running, what waits for
them, and what was made, without finding the right conversation first. Click the strip to open
or close it.

## One line while closed

The closed strip says the one thing worth knowing, in this order:

| Situation | The line |
| --- | --- |
| A task is running | `Q3 spending summary · step 2 of 4` |
| A task waits for an answer | a **waiting for you** badge on the right (with or without a running task) |
| Nothing running, tasks today | `3 tasks today · all done`, or `· 1 failed` |
| Nothing today | `No tasks today` / `No tasks yet` |

## What each task lets you do

- **Cancel task** (running or waiting) asks first, and says what else it cancels: stopping a
  task also cancels the requests sent after it **in the same chat**, which were waiting for it.
  Files it already made stay.
- **Retry** (failed or stopped) sends the same request again; a new task starts.
- **Open the conversation** goes to the chat it came from.
- Each produced file: **Open** (in the center), **Show in folder**, and, for a file the task
  **created**, **Undo**, which deletes it after a confirmation. A file the task *changed* has
  no Undo here.
- A task **waiting for you** shows the change it wants to make, as a preview of the file after
  the change, with **Allow** / **Allow for this task** / **Don't change it**, as in the
  assistant panel.

## Where the tasks come from

Nothing here is stored besides the chats' conversations; `tasksFromConversation` derives every
task from them:

| Task | Comes from |
| --- | --- |
| The task itself | one sent message (a submission) whose reply has a `data-task` part |
| Title, plan, current step, files made | the `data-task` part, which the assistant rewrites in place |
| Steps | the reply's `dynamic-tool` parts: tool name + input give the label, an error gives the reason |
| Waiting for you | a `data-approval` part with no answer yet |
| Done / failed / stopped | the settlement: `completed` / `failed` / `aborted`; no settlement means running |
| Cancel | `abort()`, which stops the running request and those queued behind it |
| An approval answer | a signal message (`sandclaw.approval`, attributes `id` and `answer`) |
