# Invite a colleague

An administrator gives a colleague access to the office machine. The colleague receives
a link; opening it in a browser is the whole onboarding. The question here is **where the
invite lives**: a focused action, or a property of the team list.

## A — Link dialog

One button, one dialog, one link. The admin names the invite (a note for themselves, not an
account) and picks a role. The link is channel-neutral: email, chat, or read aloud.

<Canvas of={Stories.LinkDialog} />

- Fast for the common case: inviting one person.
- The admin never sees who else is on the team while inviting, so duplicates are easy.

## B — Team panel

The team page is the invite surface. Pending invites are rows next to members, so the admin
sees at a glance who has joined and which links are still open.

<Canvas of={Stories.Team} />

- Makes "who can reach our AI" visible — the question a privacy-minded owner asks first.
- Heavier: the page has to exist even for a two-person company.

## Open questions

- Does an invite need a name at all, or is the link enough?
- Should an admin be able to revoke a link from the dialog (A), or only from the panel (B)?
