# Workspace layout

Sandclaw is an assistant over the user's folder, so the screen puts the documents in front and
the assistant beside them. The question: can **one dockview** look like a fixed, Cowork-style
layout to people who never touch it, and still let anyone rearrange panels?

The stories run the real `dockview-react`. Open one on its own page to use the controls. The
dashed strip under the top bar is a prototype-only control: it installs and uninstalls plugins
while the app runs.

## The contract

- **A plugin names its target zones**, most preferred first: `left`, `center`, `right`,
  `bottom`. The panel goes to the first zone the layout has. A plugin with **no target zones**
  is never placed automatically; the user opens it from **Open panel**, and it lands in the last
  active dock group.
- **A layout** says which zones exist and how big they are. Layouts are **predefined**
  (Assistant, Reading) or, later, **saved** by the user (a dockview snapshot). **Restore
  layout** lays the workspace out again from one.
- **Repair, not reset.** When a plugin is uninstalled, its panels are removed from the saved
  layout and everything else stays where the user put it. Reinstalling places the panel in its
  preferred zone again.
- **A dragged panel takes the zone of the group it lands in**, so later placements follow
  where the user put things.

## C — Fixed bars, each unlockable

The center is always a free, tabbed dock: documents open there, and their tabs can be
reordered or split. Each side bar (left, right, bottom) is **fixed** by default:
- nothing can be dropped into it;
- nothing can be dragged out of it, neither one of its tabs nor the whole bar;
- a bar holding a single panel shows no tab strip.

**Left bar**, **Right bar** and **Bottom bar** in the top bar unlock one bar at a time. An
unlocked bar shows its tab strip: its tabs can be moved anywhere, and the whole bar can be
dragged to another position by its strip. A fixed bar that holds several tabs keeps its
strip so the tabs can still be switched, but they cannot be dragged out.

How it works: dockview's own group lock only refuses drops (`locked: "no-drop-target"`);
the workspace adds the other half by cancelling any drag that starts in a fixed bar
(`onWillDragPanel` / `onWillDragGroup`).

## A — Lock toggle

Locked by default: no drag and drop, and single-panel side zones have no tab strip, so they read
as fixed areas. Zones can still be resized. **Layout unlocked** shows every tab strip and allows
dragging anywhere.

<Story of={Stories.LockToggle} inline={false} height="600px" />

## B — Always movable

No lock. Drag and drop always works. Side-zone tab strips are folded away and unfold while the
pointer is over the zone, which gives the user something to grab.

## Reading layout

The folder and the documents. The assistant's only target is `right`, which this layout does
not have, so it is left out.

## Open questions

- A, B or C?

- When a plugin is uninstalled and later reinstalled, should it go back to where the user had
  put it, rather than to its preferred zone?
