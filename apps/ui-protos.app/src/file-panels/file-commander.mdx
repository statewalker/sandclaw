# Files app — the commander

Several file panels side by side over every storage at once: a local folder (**Documents**),
browser storage, and two S3 buckets (**Archive**, **Photos**). The prototype runs on real
in-memory file systems, so copies, moves, renames and deletes actually happen, with byte
progress and a slow S3 to watch. What to look at: **how a copy or move is asked for**, **how
clashes are settled**, **what a transfer shows while it runs and after**, and **what an
unavailable storage looks like**.

## Panels

Each panel has a breadcrumb (every segment's ▾ lists the folders beside it; the first lists the
storages), Up, Refresh, New folder, a filter box, and a list sorted by name, size or date with
folders first. Clicking a panel makes it the active one (a ring); Tab moves to the next panel.
**New panel** opens a copy of the active panel's folder; *Open in new panel* on a folder opens
that folder. Every panel but the last can be closed.

Opening a file shows it in a viewer to the right of the panels: Markdown and text as text, the
rest as a placeholder naming the file and its size (the real app uses the workbench viewers).

## Copy and move

**F5** copies, **F6** moves, or *Copy to…* / *Move to…* on a row's menu. The target is the other
panel; with several other panels the dialog lists them, the most recently used first, and the
folder stays editable. Dragging between panels opens the same dialog with **Move** chosen
(Copy when Ctrl / ⌥ is held); dropping on a folder row or a breadcrumb segment targets that
folder, and a storage's row in *All storages* targets that storage's top. Files dragged in
from the desktop open it too, without Move.

- **One item**: its name can be changed; when the target already has that name the dialog says
  "*name* already exists — it will be replaced."
- **Several items with clashes**: one choice for all of them: **Overwrite**, **Keep both**
  (the default: `offer copy.pdf`), **Skip**.
- **Into its own folder**: "Same folder: a copy is made beside it." A move there would do
  nothing, so it becomes a copy with a free name.
- **A folder into itself**: refused in the dialog, the button disabled.

## While it runs, and after

The strip at the bottom shows the current file, a bar, bytes and items done ("34 MB of 120 MB ·
3 of 7 items") and Cancel. Cancel stops in the middle of a file and removes the incomplete copy;
the source is untouched. At the end: **Done**, **Cancelled**, or "2 of 7 failed" with each
failed item and its reason. A failed item does not stop the others. Afterwards both panels are
listed again and the target panel selects what was written.

An overwrite never removes the old file before the new one is complete: if the copy fails, the
old file keeps its content.

## A storage that can't be used

A locked vault or a bucket that does not answer is never an empty folder: the panel shows the
reason and its action (Unlock, Retry; here the action only says "Opens Settings → Storage").
The Copy / Move dialog says so too, as soon as its folder points there: the reason, Unlock or
Retry, and the button disabled. Nothing starts until the storage can be used.

## New folder, rename, delete

F7 and F2 ask for a name, refuse names with `/` or `\` and names already in the folder
("*name* already exists here."). F8 or Delete asks first and says what matters: "Local folders
and S3 have no trash: this can't be undone."

## Phone

Below 640 px one panel shows at a time, with a tab per panel. Drag and drop is off (unreliable
on touch screens); each row has a **⋯** that opens its menu, and Copy to… / Move to… go through
the same dialog. An opened file takes the panel's place until its tab is chosen again.

## A — Dock panels side by side (built)

Any number of panels, resizable, each with its own toolbar; commands live on the rows (menu,
F-keys, drag). It matches the workbench dock the app is built on, where panels and viewer tabs
sit together, and it scales from one panel on a phone to four on a wide screen.

## B — A fixed two-pane commander (not built)

Midnight Commander's shape: exactly two panes, a shared command bar along the bottom with the
F-keys spelled out (*F3 View · F5 Copy · F6 Move · F7 Folder · F8 Delete*), and the target is
always "the other pane". Very learnable for those who know it, and the bar teaches the keys to
those who don't. But it caps the work at two folders, does not fit the dock or a phone, and the
key bar takes a row on every screen.

**Leaning: A**, with B's one good idea kept as a hint: the F-key next to each menu item, as now.

## Decisions assumed (from the design)

- A plain drop within one storage pre-selects **Move**; across storages, or with Ctrl / ⌥, it
  pre-selects **Copy**, since a move there deletes the original.
- Nothing changed while a transfer runs is lost: a name taken meanwhile is never replaced (one
  item is replaced only after the dialog warned about it), and a move leaves at the source
  anything added or changed while it copied.
- **Keep both** is the default for clashes; one choice covers every clash in a batch.
- An overwrite replaces the old file only with a complete copy; an overwritten folder is
  replaced, not merged.
- A cancelled or failed copy leaves nothing partial: a file or folder appears under its name only
  once it is complete (a cancelled folder copy keeps none of the files already copied).
- A failed item does not stop the batch; the summary lists each failure with its reason.
- Delete is permanent on every storage, and the confirmation says so.
- Phone width: one panel, no drag and drop, commands through the menu.
