# AI models

The admin's screen for the models LiteLLM serves, which model does which job (chat, summaries,
the search index), and who uses how much. Members hold no LLM keys: the hub holds them and calls
the models for everyone, tagging each call with the person and the device (peer) it came from.
That tag is the point of the screen. It answers two questions a small team asks about AI:

- **Privacy**: which machine sent what to which model. Every model is marked **Stays in the
  office** (runs on the hub) or **Sent to Anthropic / OpenAI** (the text leaves the office), and
  the daily bars split the tokens the same way.
- **Cost**: tokens and an estimated price, per person, per device and per model. A person owns
  several devices, so a person unfolds into their devices: the phone that sends little, the
  laptop that indexes the folder.

The screen stays basic. Everything else (providers, limits, logs, keys for programs outside the
group) is in the full LiteLLM UI, which the hub proxies and an admin opens in its own tab.

## A — One page

Jobs, models and usage on one scroll; "Open LiteLLM admin" in the header opens the LiteLLM UI in
a new browser tab. Everything is visible at once and the page reads top to bottom: what does
what, then what it cost. With a period selector and two groupings the usage part gets long, and
on a phone the bars are far below the jobs.

## Changing which model does a job

Picking another model never applies at once: a confirmation says what changes, in plain words.
The search index is the expensive one: a new embedding model means indexing every file again,
and moving it to a cloud model sends the text of every file out of the office. Moving chat to
the hub's model says the opposite: text stays home, nothing to pay, slower answers.

## Open questions

- A or B? A keeps everything in sight; B fits a phone better and keeps LiteLLM inside Sandclaw.
- Cost in dollars (what providers bill) or in euros (what the team pays)? Leaning dollars with a
  "converted" hint later.
- Should members see their own usage (their devices only), or is usage admin-only?
- One model per job for the whole group, or may a person keep sensitive work on the hub's model?
- Should the admin set a monthly budget that warns, or is the estimate enough?
- When chat's model is down, should the hub fall back to another model on its own, or wait for
  the admin?
